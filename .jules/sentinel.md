## 2024-03-24 - [CRITICAL] Cross-Site WebSocket Hijacking (CSWSH) and Missing Security Headers
**Vulnerability:** The WebSocket server in `serve.py` uses `websockets.asyncio.server.serve`, which by default does not validate the `Origin` header during the WebSocket handshake when intercepting connections in `process_request`. This means that if a user visits a malicious website, the malicious site can connect to the local LiveLink agent WebSocket (e.g., `ws://localhost:8000`) and interact with it, hijacking the agent session. In addition, HTTP responses on `/health` and `/` endpoints are missing essential security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`) to mitigate XSS and Clickjacking risks.
**Learning:** In local agent runtimes that listen on `localhost` or `0.0.0.0`, lack of strict Origin validation in custom WebSocket handshake processors allows arbitrary external websites to bypass the Same-Origin Policy and control the agent.
**Prevention:** Always validate the `Origin` header against the expected host/port during the HTTP upgrade request if CORS is disabled, or use explicit allowlists. Always set security headers on any HTTP response served by the WebSocket server to ensure defense-in-depth.
