## 2025-02-14 - [CRITICAL] Cross-Site WebSocket Hijacking (CSWSH) in Local Dev Server
**Vulnerability:** The built-in local development WebSocket server (`agent.serve()`) lacked Origin header validation, making it vulnerable to Cross-Site WebSocket Hijacking. An attacker could host a malicious website that opens a WebSocket connection to `localhost:8000` (or whichever port the user runs it on), bypassing Same-Origin Policy (SOP) since WebSockets don't inherently enforce it, and interact with the developer's local agent or steal data.
**Learning:** Development servers running locally are highly susceptible to CSRF/CSWSH because browsers will attach local cookies/session context (not strictly applicable here, but the connection itself is unrestricted) and route requests to `localhost`. Without explicit Origin validation, any external tab can initiate a WebSocket connection to the local service.
**Prevention:** Always validate the `Origin` header against the expected `Host` or a strict whitelist of allowed origins during the WebSocket handshake (`process_request` in `websockets` or equivalent `upgrade` handler), especially for local dev tools where developers often browse untrusted sites while the server is running.
